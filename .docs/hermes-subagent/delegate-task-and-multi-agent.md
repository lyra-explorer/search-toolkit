# Hermes delegate_task / Multi-Agent 仕組みまとめ

## delegate_task とは

Hermes の `delegate_task` ツールは、独立したサブエージェントを起動してタスクを委譲する仕組み。
親エージェントは結果のサマリだけを受け取り、中間の思考プロセスはコンテキストウィンドウを消費しない。

## 動作確認済みの挙動

### セッション構造

```
親セッション (20260518_173421_eeda33)
  ├─ API call #1: ユーザー要求を受け取る
  ├─ tool terminal: ローカル環境準備
  ├─ API call #2: タスク分析
  ├─ tool delegate_task: サブエージェント起動
  │   └─ 子セッション (20260518_173446_3fa326)
  │       ├─ 独立した会話履歴 (history=0)
  │       ├─ 独立した terminal session
  │       └─ 同じモデル (grok-4.3) / 同じプロバイダ (xai-oauth)
  └─ API call #3: サブ結果を受け取って最終回答
```

### ログから読み取れるパラメータ

| パラメータ | 値 | 備考 |
|-----------|-----|------|
| モデル | 親と同じ grok-4.3 | モデル指定の変更は未検証 |
| プロバイダ | xai-oauth | |
| history | 0 | サブは履歴を引き継がない |
| platform | cli | |
| max_spawn_depth | 1 | サブエージェントはさらにサブを spawn しない |

## 制約

- **記憶がない**: サブエージェントは context パラメータで必要情報をすべて受け取る
- **同じモデル**: 現状は親と同じモデルが使われる。別モデル指定は未確認
- **深さ制限**: max_spawn_depth=1 で、サブがさらにサブを作ることはできない
- **結果は配列**: 複数サブを起動した場合、結果が配列で返る
- **並列制限**: delegation.max_concurrent_children で同時起動数を制御

## 「二人で相談」の実際

「さらに二人で相談して決めてくれ」という指示に対し、Hermes は:
1. 親がユーザーの意図を解釈
2. `delegate_task` でサブエージェントを起動
3. サブに "The user wants us (two agents) to further discuss..." というメッセージを渡す
4. **同じ grok-4.3 同士** が会話する

課題: モデルが同じなので「別視点」にはなりにくい。GLM-4.3 と grok-4.3 を組み合わせるなど、マルチモデル構成にすると価値が出る可能性がある。
